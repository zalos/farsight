- `scripts/changelog.mjs` + `scripts/release.mjs` — the release pipeline's local half (zero dependencies; `docs/RELEASING.md`). `changelog.mjs` reads `<since>..HEAD` — `--since`, else the newest reachable `v*` tag, else the commit that seeded `CHANGELOG.md`'s newest section — parses conventional subjects and `BREAKING CHANGE:` footers (merges and `chore(release): vX.Y.Z` commits skipped, non-conventional subjects under *Other*), and renders the `CHANGELOG.md` section (`--write`, below an `## [Unreleased]` head) and the release-notes body with its install block (`--notes`). `release.mjs` computes the next version (`--bump`/`--version`/`--prerelease`), refuses a dirty tree, a non-`main` branch without `--allow-branch`, a used tag or a version that does not move forward, bumps only the root `package.json` (what `pack.mjs` and `buildInfo()` read), writes the changelog, commits `chore(release): vX.Y.Z`, tags it annotated with the notes verbatim (unless `--no-tag`; `--branch 'release/v{version}'` commits on a new branch, `--commit-notes` commits the notes as `.github/release-notes/vX.Y.Z.md`), and sets `GITHUB_OUTPUT` (`version`, `tag`, `prerelease`, `notes`, `commit`, `branch`, `tagged`) for `.github/workflows/release.yml`, which opens the release PR; `.github/workflows/publish.yml` tags and releases after it is squash-merged (a squash subject's ` (#N)` is read as the PR and printed as a link). It never pushes. **`scripts/lint-commits.mjs`** — the Conventional Commits rule (`TYPES`, `SCOPES`, `MAX_SUBJECT`; `lintSubject`/`lintRange`; `--message` for a PR title, `--file` for the `commit-msg` hook, `--range` for CI's `commits` job, `--any-scope` for branch commits) and **`scripts/install-hooks.mjs`** — run by the root `prepare`, copies `.githooks/*` into `.git/hooks` (never `core.hooksPath`, so the LFS hooks stay) and sets `.gitmessage` as the commit template; a no-op under `CI` or outside a checkout. Tests: `scripts/test/*.test.mjs` against throwaway git repos (`pnpm test:scripts`, part of the root `pnpm test`).
- `scripts/synth-graph.mjs` — a seeded, deterministic synthetic workspace graph in the current schema, for performance work (never ingested from code; write it into a scratchpad or `build/`). `--preset full` (default): 20 sources · 1,000 NX projects (per source 4 web apps, an API app, 2 e2e projects and libraries layered feature → ui · data-access → util, tagged `scope:` / `type:` / `platform:`) · ≈245k nodes · ≈418k edges · 300 flows in 40 manifests, ≈410 MB; `--preset small` (CI): 4 sources · 52 projects · ≈18k nodes · 40 flows in 8 manifests. Every code node carries `project`; modules import the workspace packages of the libraries their project depends on (counted into `meta.projects.imports`) and third-party packages; functions, components, classes, rules, tests (`covers` static / observed / declared, runs on most), routes in the API app (`contains` from an `api` node, `guards`, handlers), client `http` edges, data access `reads` / `writes` tables (a Postgres store) and store-like externals, pages under design manifests with flows that `renders` 3–7 screens in order, personas and groups in `meta.journeys`, work items with `tracks`. Flags `--sources --projects --nodes --flows --manifests --seed --out --settings <dir>` (the last writes a workspace settings file naming every source). The header comment documents the shape. `e2e/perf/` (`pnpm e2e:perf`, `scripts/e2e-perf.mjs`) serves it and measures every surface (docs/CI.md § The perf suite); `packages/server/test/thousand-perf.test.ts` holds the folds to budgets on the small preset.
