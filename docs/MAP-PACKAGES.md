# Package map — what lives where

Ingest declaration health lives in `packages/parsers/src/shared/declared-paths.ts`: config import/setup/plumbing
bindings and unresolved decision affects become ingest warnings using existing metadata. Source selection,
including nested `.gitignore` rules, lives in `packages/code-parser/src/shared/files.ts`. Nest body-schema
declarations are read in `packages/code-parser/src/nest.ts` and resolved to rules in `tsjs.ts`.

> Moved out of `AGENTS.md` so it is not read at the start of every session. This is the reference: open it when
> you need to find something, not to orient. `AGENTS.md` keeps the contract, the commands and the gotchas.

- `packages/echo` — optional standalone memory companion. One workspace selects one local or shared global
  profile; Farsight has no runtime dependency on it. See [ECHO.md](ECHO.md) for the preview scope and
  [SECURITY.md](SECURITY.md#echos-separate-local-boundary) for its separate trust boundary.

  | `trust.ts` | private user-state receipts for exact configuration/connection bytes and credential-origin pins |
  | `installation.ts` | local/global resolution, one workspace connection pointer, preflight, backups and pointer removal |

  | `models.ts` | bounded Ollama and OpenAI-compatible requests; model listing, explicit summaries, structured sub-mind generations, exact request accounting and remote transport policy |

  |---|---|

- `packages/sentinel` — optional security review package (ADR 18). Draft contracts and generated schemas, and a
  draft local store (ADR 19); no scanner, container or model runtime yet. `src/store/index.ts` is the store's
  public facade (`openStore`, also re-exported from the root and as `./store`); behind it `runtime.ts` (the SQLite
  release gate), `paths.ts` (canonical, local, owner-only folders), `owner.ts` (the lifetime owner lock and epoch),
  `ledger.ts` + `migrations.ts` + `store-types.ts` (the fenced WAL ledger), `objects.ts` (content-addressed objects),
  `objects-ledger.ts` (the ledger seam and verifier) and `gc.ts` (read-only reachability and the dry-run prune plan).
  `test/store-integration.test.ts` drives the facade end to end across processes. `src/snapshot/index.ts` is the
  capture facade (ADR 20; also `./snapshot` and the root): `git.ts` (a read-only Git object reader, no git process),
  `committed.ts` and `worktree.ts` (the two enumerations), `inventory.ts` (entries, budget, quota, case collisions,
  LFS), `policy.ts` (capture policy and path rules), `materialization.ts` (the provenance sidecar), `capture.ts` (stage,
  write, recheck, admit), `materialize.ts` (reopen and restore from the store alone) and `reconcile.ts` (E1). The
  ledger's `admitSnapshot`/`getSnapshot` and schema step 2 (`snapshots`, the rebuilt event log) admit a snapshot
  without a run. `test/snapshot-*.test.ts` builds real Git
  fixtures with the git CLI; capture itself never runs it. Depends only on graph, code-parser and core; nothing in the
  Farsight application depends on it, and `farsight-cli` neither bundles nor starts it. Its schema tests run in
  `pnpm -r test`. `scripts/pack-sentinel.mjs` builds the separate `farsight-sentinel` tarball from the
  manifest's `bin` and root export; `scripts/test-sentinel-package.mjs` installs it into a clean npm consumer and
  checks `--help`, the import, the packaged schemas and that no Farsight package arrives with it.
  `scripts/test-farsight-package.mjs` is the converse: `farsight-cli`, packed from the CLI's build closure alone
  (`scripts/pack-preflight.mjs`), installs, ingests and serves with no Sentinel present;
  `scripts/test-farsight-package-absent.mjs` repeats it in a temporary workspace copy without `packages/sentinel/`. Both run in the
  `sentinel-package` CI job; `scripts/npm-consumer.mjs` is their shared `npm init -y` consumer.
