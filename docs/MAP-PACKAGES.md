> Moved out of `AGENTS.md` so it is not read at the start of every session. This is the reference: open it when
> you need to find something, not to orient. `AGENTS.md` keeps the contract, the commands and the gotchas.

`journey-counted.ts`: `withJourneyCounted()` is `journeySummary()`'s tail and hangs `counted` on the summary and on every segment; `coverage.ts` `evidenceFacts()` gives every coverage scope `counted` + `observation` and the evidence word with its business sentence, plus `coverage.moments` per action; `testsSurface(…, { level })` filters every count and adds `countsAll`/`counted`/`sources[].runs`; `storybook.ts` `storyCounts()`/`storyParts()` — own · docs pages · the parts' stories. **The ledger of every printed number and what it counts is `docs/COUNTS.md`.**). **Work items in the graph** (`work-graph.ts`, work-items-sync.md §9): `workNodeOf()` (`work::<source>::<key>`, no `loc`, title as the business label, `work · provider: · state: · type: · source:` tags, the tracker URL as a link), `tracksEdgeOf()` (declared → `annotation-scan` HIGH; - `packages/parsers` — **`ingestRepo()` in `index.ts` is the only ingest entry consumers use** (registry runs every adapter, merges fragments per repo, then runs the OpenAPI post-pass: `openapi/` = `yaml`-backed reader with operation line numbers, discovery by filename/content/`farsight.config.json → openapi`, `applySpecs` reconcile into the fragment, `ingestSpec` for a spec-only source by file or URL; `options.openapi:false` skips it; then the tests post-pass: `tests/` = `cases.ts` claims spec files by glob or runner import (they keep `file` + `imports`, stop producing `function` nodes) and extracts `describe`/`it`/`test` cases (`.skip`/`.todo` — or anything under `describe.skip` — is `inactive`, its static edges carry `meta.inactive`), `covers.ts` resolves `@covers` (file header + case JSDoc; never split on spaces; unresolved kept on `test.declares`) and infers static edges (imports via aliases, `render(<X/>)`, `page.goto`, `request.<method>`, e2e helpers one level), `reports.ts` reads istanbul / vitest / playwright / junit reports named in `farsight.config.json → tests` fail-soft (run-level synthetic test node for istanbul carrying the report's file set; one `TestRun` per Playwright project with `flaky` and retries kept, `run` = the weakest fold; `.each` rows join their template; `freshness` compares the recorded digest to the repo's **content digest** first — `contentDigest()`/`repoContentDigest()` in `shared/files.ts`/`index.ts`, `meta.sourceDigest`, `GraphStore.repoMeta()` — then the legacy mtime hash), `gaps[]` as ordered data (missing-artefact → … → no-config) with `blindSpots` derived and folded `×n`, `reports[]` one entry per matched file plus one per zero-match glob, an idempotent re-import; `options.tests:false` skips it; then (last) the stories post-pass: `stories/index.ts` `applyStories` — every `*.stories.*` file's CSF default export + named exports become `StoryRef`s on the node `component:` names (imports and barrels followed), `.storybook/main.*` discovery with its `stories` globs, the port read off `project.json`/`package.json` and the root script that starts it, merged with `farsight.config.json → storybook`; misses land in `meta.stories.unresolved` with a reason; `options.stories:false` skips it; before that the design post-pass: `design/` = `screens.json` discovery by name or `farsight.config.json → design`, Figma `lastModified` freshness with `FIGMA_TOKEN` (fail-soft), `applyDesigns` reconcile, `ingestDesign` for a design-only source; `options.design:false` skips it; `farsight.config.json` itself is applied inside `ingestRepo` — see gotchas). Unmatched `fetch()` calls become `unknown` "?" stubs (relative) or `external` hosts (absolute), never dropped; every `http` edge carries a `resolution`. `shared/` = language-agnostic layer (file walk/globs/freshness, JSDoc/TSDoc/Javadoc doc harvest, `// @business` branch labels, tags/normalizePath). `treesitter/harness.ts` = WASM grammar loader/walker (`@vscode/tree-sitter-wasm` — prebuilt, no native deps) that future language adapters build on. `java/` = Java/Spring adapter (`index.ts` graph assembly, `spring.ts` annotation semantics, `branches.ts` Journey forks): mapping annotations → routes, method security + `@guard` → guards, `@Entity` → tables with columns, Spring Data repos → reads/writes with query text, Bean-Validation DTOs → rules + `@Valid` validates, Kafka/Rabbit publishes/consumes, `@Scheduled`/`main`/listener entrypoints, DI field-type call resolution. `tsjs.ts` is the TS/JS adapter (oxc-parser, heuristic extraction: functions, **deferred and tx flags** from an ancestor scan of every call site (a function expression that is an object-literal property value is deferred — journeys skip it; one passed straight to `withOps/withTenant/withTx/transaction/$transaction` is `tx`; call arguments are never deferred, so the submit transaction stays the caller's), **property-value callbacks as nodes** (`host.keyPath`, tag `callback`, their own body walk) with **hook bindings** (`new K({ hooks: { fn } })` ↔ `this.<field>.<path>.fn()` in K's methods → `hook-binding` MEDIUM, deferred), the **setup heuristic** (`x ??= build()` in a `Symbol.for`/`globalThis` file tags the builder `setup`), `env-schema` tags on `*EnvSchema`/`*ConfigSchema` rules and rules in `env.ts`/`config.ts` (journeys skip them as gates, `rulesFor` keeps them), **externals** from three sources (an SDK specifier the table knows → `sdk-import`; a non-literal `fetch` in a class whose base URL starts with an UPPER_SNAKE constant → `constant-host`; `farsight.config.json → externals` `<path>::<Class>` renames/re-kinds, or gives every fetching method an edge) — created only when an edge reaches them, **interface-typed dispatch** (a member call on a typed parameter or `this.<typed field>` resolves through the declared type to its production implementers — class self, `implements`, the name-suffix fallback only when nobody declared themselves — one edge each, `interface` MEDIUM with the doubles in `resolution.alternatives`; a named type nothing implements tags the caller `unresolved:interface` and never falls back to the method-name guess, except a hook-shaped chain which falls back to its binding), **class methods as `Class.method` function nodes grouped under the class** (`this.x()` resolves to the sibling; a member call `a.b.m()` resolves by method name to the one class that declares it — in-memory / mock / fake twins step aside, the receiver's word picks between survivors, ambiguity stays an absence — stamped `technique: 'method-name'` MEDIUM), **raw SQL** (`shared/sql.ts`: `CREATE TABLE` in any string → table nodes with columns at the migration's line; FROM / JOIN / INSERT INTO / UPDATE / DELETE in a template or string literal → reads / writes from the function that runs it, the statement as the edge's code; comments stripped), **Azure Storage Queue** clients (`getQueueClient(NAME)` + `sendMessage` / `receiveMessages` → publishes / consumes, the name followed through imported constants and barrels), components, `page` nodes from React-Router/Angular route configs **and Next.js App Router conventions** (page/route/layout/middleware files, `'use server'` actions as routes), `renders` edges from JSX, calls-via-imports, Express + App Router routes, guards (detected, `@guard` JSDoc, or config-declared — **a guard with a body keeps its `calls` edge** (`meta.via: 'guard'`) beside the `guards` edge, so `journey()` walks a guard that also works — the submit transaction — and keeps a guard that only checks as a badge; default `maxSteps` is 1200), zod rules, db edges (`db.table.op`, Drizzle builder chains + relational API, `pgTable` schema → table nodes) with query code, fetch→route stitching, doc-comment parsing (`@business @group @tag @guard @entrypoint` + vanilla JSDoc/TSDoc/Javadoc harvest: summary-sentence business fallback, `@deprecated`/`@see`/`@since`/`@remarks` → docs, TSDoc modifiers → tags, inline `{@link}`/`{@code}` stripped; `// @business` comment directives label branch points/arms — see docs/ANNOTATIONS.md), glob excludes, freshness meta). `aliases.ts` resolves bare import specifiers (tsconfig `paths`, npm/pnpm workspace packages); barrel re-exports are followed during symbol lookup. `walk.ts` has the AST walker. **Work keys on the spine** (`shared/git.ts`): `gitLog` reads `%b` bodies, `after` for an incremental read, and with `keyRefs` walks the key-bearing branches too (`default..ref` → `via: 'branch'`; a merge naming a branch → its `M^1..M^2` commits `via: 'merge'`); `gitShowPatch` (one commit, bounded, sha-checked); `commitInputsOf(commits, { opts, detect })` is the one mapper to `SnapshotDb.writeCommits` (keys absent = not read). `@work KEY` is the sixth doc tag (`shared/docs.ts` → `work:<KEY>` tags); `screens.json` `work: []` on screens and flows lands the same way (core `design.ts`).
- `packages/server` — HTTP server (binds 127.0.0.1 only): viewer + `/graph` + `/api/settings` (GET/PUT) + `/api/sync` (re-ingest sources; git sources clone/pull into `.farsight/cache`; writes a snapshot per sync) + `/api/journey?entry=<node id>` (execution timeline with full code slices read from `roots[repo]`, path-confined, fail-soft) + `/api/stories[?node=&refresh=1&scope=]` (`?node=` also answers `counts: {own, docs, parts}` and `parts` — `storyCounts`; the Storybooks the graph recorded, reachable or not, how each index mapped onto nodes, every component's stories with the frame URL — core `storybookLive`; read only, never starts one; a source's `storybook.url` in settings overrides the recorded URL; the viewer page is served with `Content-Security-Policy: frame-src 'self' <recorded Storybook origins>`) + `/api/strings` (the two-register catalog) + `/api/modelhub/state` (runtime AI overlay — not part of the semantic graph) + `/api/apis[?scope=]` · `/api/apis/<id>` (operations with contracts + consumers) · `/api/apis/<id>/spec` (raw spec text, path-confined) · `/api/openapi?repo=&format=yaml` (generated) · `POST /api/apis/diff {spec|url|path, repo}` (proposed spec vs code, stores nothing) + `/api/design[?scope=]` · `/api/design/<id>` (screens with status, drift, enriched nodes) · `/api/impact?node=&hops=&tests=` (what depends on a node, per hop, with its bound) · `/api/history?repo=&from=&to=` · `/api/changes` · `/api/design/image?node=<id>` (a repo-relative image path-confined, or a Figma render fetched with `FIGMA_TOKEN` and cached under `.farsight/cache/design/`) · `POST /api/design/diff {manifest|url|path, repo}`; `/api/journey` also returns `screens` (the SCREEN band) and `plannedCount`, and resolves `?entry=<name>` like the MCP tool; sources may be `type: 'openapi'` (a spec file/URL with no code) or `type: 'design'` (a screens manifest with no code). Viewer = `public/viewer.html` (markup/CSS/SVG sprite) + ES modules under `public/app/` (no build step; served path-confined). **The viewer modules are parsed by Farsight's own ingest** — functions carry JSDoc `@group` tags ("Settings page", "Inspector", "Graph rendering", "Shell", "Keymap", …) so the GUI shows up in the dogfood graph; keep those tags when editing. **Work items** (`src/work.ts`, ADR 10–12 / work-items-sync.md §9–10): `Source.type` gains `'work'` with the §10 fields (secrets only as `keychain:` references — GET /api/settings serves the file back); `syncSources()` skips work sources in the code loop, then writes each code source's commit spine (`writeSpine`: ≤ 500 commits, incremental while the key rules are unchanged, keyed commits' hunks → `commit_node`; fail-soft *history not indexed: …*), runs work sources through the engine (fixture, Jira and Azure DevOps registered at the top of `work.ts`), and joins (`joinWork`: declared `work:` tags + commit keys → `link` table + `work` nodes/`tracks` edges; a declared key no source can hold is `unmatched` with a reason). `handleWorkRoute()` serves `/api/work`, `/item/<id>`, `/item/<id>/diff?sha=`, `/links?node=`, `/flow/<id>`, `POST /sync`, `POST /intent` (+ `/<id>/confirm|drop|rebase`), `/outbox`, `/audit`, `/people`, `/states`; 503 when the work cache cannot open.
- `packages/mcp` — agent surface (`run.ts`: `createMcpServer(graph)` registers every tool unconnected — `runMcpServer` puts it on stdio for `farsight mcp`, `test/mcp-tools.test.ts` puts it on the SDK's in-memory transport against an ingested copy of `examples/invoice-app` with two syncs).
