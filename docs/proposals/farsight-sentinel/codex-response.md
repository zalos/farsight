## Finding dispositions

| Review finding | Decision | Reason and resulting change |
|---|---|---|
| 2.1 Repository baseline and parser extraction | Accepted | **issue (blocking): consume the merged extraction contract.** All five documents are re-pinned to `4fce1c8`; Phase 1 consumes `parseRepository()` and the portable graph with occurrence evidence. The application ingestion path is optional enrichment under explicit network/environment restrictions, never the coverage denominator. Updated package, file-outcome, occurrence and incrementality rows use moved code citations. Code inspection also settles the review's open question: `ingestRepo()` calls the lower-level extraction without the bounded read context and does not return its outcome ledger; E1 validates the resulting coverage design rather than deciding whether those fields currently exist. |
| 2.2 Four ways to imply clean coverage | Modified | **issue (blocking): preserve unknowns and skipped work.** Spring and Express/Nest protection remains unknown until the relevant framework-order capability runs; required unsupported checks cannot clear findings, and matcher-aware Next coverage is the first TS/JS layer deliverable. The independent inventory covers security inputs beyond the parser, prints `seen by no stage`, and records scanner granularity/skips. Inventory classes need precedence because generated code can also be parsed, and inaccessible directory descendants have unknown cardinality. Existing generated source may be captured without a build. No scanner's per-file skip fields are assumed until verified against its pinned version. |
| 2.3 Licenses and offline behavior | Modified | **issue (blocking): separate distribution rights, analysis capability and network effects.** Original local rules, telemetry disabled, pinned tools and Sentinel-owned fingerprints are adopted. CodeQL is user-installed with attested applicable terms; Opengrep is a candidate default pending E3. Scanner research retains short exact license excerpts and the supplied sources, adds the alternatives, and separates dependency resolution, database fetches and telemetry. The review overstates Bearer CLI's cross-file capability, simplifies CodeQL's permitted-use categories, overlooks the rules repository's LICENSE, conflates Trivy fallback mechanisms and understates possible offline resolved-input evidence; the corrections below govern implementation. |
| 2.4 Differential reuse and finding identity | Modified | **issue (blocking): changed analysis is not a fix.** Framework versions enter layer fingerprints; narrowed rules, engine changes and capability changes produce `changed detection` unless a reviewed compatibility mapping establishes comparable coverage. LOW-confidence edges are re-resolved when candidate declarations change, including unchanged callers. Occurrences are snapshot anchors, with a separate versioned cross-run matcher and explicit probable/ambiguous matches. SARIF keeps rule-family IDs stable, but a Sentinel issue hash cannot stand in for GitHub's source-line hash; those are separate fields. |
| 2.5 Deployment assertions and dispositions | Accepted | **issue (blocking): an unverified control cannot satisfy the finding policy.** Added `DeploymentAssertion` with owner, deployment/environment scope, evidence, expiry and provenance level. Disposition scope is bounded by finding scope, with partial mitigation per path. New entry points, reduced resolution confidence, framework changes and expiry reopen dependent assessments. The next evaluation records `reopened: disposition expired`; historical reports retain their pinned evaluation time. Assertion provenance does not add application-graph evidence classes. |
| 2.6 Child worker simplification | Modified | **suggestion (non-blocking): simplify leases while retaining stale-result protection.** Owned child workers use process supervision and coordinator epoch/attempt checks, without heartbeat leases. External claims keep lease renewal and fencing generations. The review's claim that process groups prevent children outliving their coordinator is false, so restart includes verified owned-process cleanup before replacement. Cancellation records confirmed spend or unknown usage rather than assuming every interrupted call was billed. Initial heavy-analyzer concurrency is conservatively one, plus one budgeted model request, pending E8; per-core heavy workers are not a measured memory-safe default. |
| 2.7 Agent evaluation and provider disclosure | Modified | **suggestion (non-blocking): measure accuracy and disclosure explicitly.** Reports gain per-model agreement, related-issue and coverage distinctions; labeled repeated trials measure under-reporting because deterministic output is not ground truth. Provider retention/training terms, intended disclosure, host-reported identity, estimates and token/cost limits are recorded. Evidence tools cannot fetch arbitrary URLs and rendered output cannot load remote content automatically. Canary trials are an empirical release gate, not proof that comment instructions can never affect verdicts. E3/E5 thresholds and provider choices remain unanswered owner questions; uncertain metering stays visible. |
| 2.8 One optional package | Accepted | **suggestion (non-blocking): use one package and a narrow host bridge.** `packages/sentinel` owns its bin, stdio MCP entry point, contracts and engine without a viewer/server dependency. The worker protocol stays versioned. An implementation PR records one ADR and package-map entry; this documentation does not declare unimplemented architecture shipped. Split a second package only when a real consumer needs that boundary. |
| 2.9 Ledger, codecs and artifact ownership | Modified | **suggestion (non-blocking): gate the actual runtime and retain independent artifacts.** Record and check `process.versions.sqlite`; accept verified fixed releases rather than a simple numeric floor that admits withdrawn 3.52.0. The selected installed Node 24.21.0 reports SQLite 3.53.4; that does not establish every shell's runtime. Gzip remains initial, built-in experimental zstd is a future feasibility comparison, and Sentinel owns a copy of referenced graph artifacts. `/graph` isolation remains an implementation invariant and E8 measurement, not a test performed for this revision. |
| 2.10 Standards and export limits | Accepted | **suggestion (non-blocking): retain versioned standards and consumer limits.** Research keeps OWASP/CWE/ASVS pins, GitHub SARIF limits including the 5,000-result displayed subset, stable rule families, OpenVEX's narrower purpose, negotiated MCP capabilities and Temporal's at-least-once activity caveat. The complete local report remains authoritative. The source-line fingerprint qualification in 2.4 also applies here; no platform-specific projection replaces Sentinel's evidence ledger. |
| 2.11 Remaining contract details | Accepted | **nitpick (non-blocking): make the examples explicit.** Added `status --wait` and submission-only detached behavior, per-adapter `tools.lock.json` pins, parser artifact usage and framework-version provenance. Semgrep CE's intrafile analysis may include cross-function behavior within one file; it is not general interfile proof. The five owner questions are at the top of proposal §9 verbatim, including candidate versions; no supported-version list is selected by this revision. |

## Verified corrections and limits in the review

These qualifications are based on code at `4fce1c8` or primary sources, not results from the deferred experiments.

| Review claim or proposed wording | Verified correction and evidence |
|---|---|
| `ingestRepo()` diagnostic retention needs E1 to establish | The call is `extractRepository()` at [parsers/index.ts:94](../../../packages/parsers/src/index.ts#L94). Without a `RepositoryRead` context, `fileStatus()`/`parseError()` have no ledger to update at [repository.ts:193–204](../../../packages/code-parser/src/repository.ts#L193). Sentinel must consume the artifact API separately. |
| E1 can currently expect parse-error path and line | The diagnostic type permits a line, but calls at [tsjs.ts:386–391](../../../packages/code-parser/src/tsjs.ts#L386) and [java/index.ts:107](../../../packages/code-parser/src/java/index.ts#L107) omit it. E1's line requirement is a future contract improvement, not an existing API guarantee. |
| A Figma token alone causes an enrichment request | [design/index.ts:61–65](../../../packages/parsers/src/design/index.ts#L61) requires a file key and token; `design: false` skips the pass. Network-denied execution and explicit local inputs remain necessary because optional enrichment has several effects. |
| Occurrence IDs solve cross-revision identity | [portable.ts:24–38](../../../packages/graph/src/portable.ts#L24) hashes relationship, location and span, and rehashes when retargeted. Stable for identical evidence is not stable through moved spans or renames; exact/probable/ambiguous matching remains required. |
| Bearer CLI supplies the proposed deep cross-file slot | The [Bearer README](https://github.com/Bearer/bearer) attributes advanced cross-file analysis to Pro. CLI stays an additional SAST candidate; no Pro capability is attributed to the CLI. |
| CodeQL has one blanket private-code condition; the Opengrep rules page has no license | [CodeQL terms](https://github.com/github/codeql-cli-binaries/blob/main/LICENSE.md) distinguish several use categories and restrictions; scanner research quotes the relevant short terms and records user-attested use basis. The [opengrep-rules LICENSE](https://github.com/opengrep/opengrep-rules/blob/main/LICENSE) exists and includes LGPL 2.1 plus Commons Clause. Original Sentinel rules avoid treating a fork as redistribution permission. |
| Trivy checks and databases share registry fallback; offline Maven necessarily means direct-only coverage | [Trivy database documentation](https://trivy.dev/latest/docs/configuration/db/) distinguishes database registry fallbacks from embedded checks fallback. [OSV resolution documentation](https://google.github.io/osv-scanner/supported-languages-and-lockfiles/) disables online transitive resolution offline, but pinned lockfiles/SBOMs/imported resolution can supply further evidence. Missing manifest versions and transitives remain gaps. |
| Local workers cannot outlive their coordinator | [Node 24 child-process documentation](https://nodejs.org/download/release/v24.21.0/docs/api/child_process.html#optionsdetached) explicitly allows children to continue after parent exit. Keep coordinator-only publication, epochs, attempt checks and owned-child cleanup while dropping unnecessary child heartbeat leases. |
| Sentinel's fingerprint can populate GitHub's primary line hash | [GitHub SARIF support](https://docs.github.com/en/code-security/reference/code-scanning/sarif-files/sarif-support) and its [fingerprint implementation](https://github.com/github/codeql-action/blob/main/src/fingerprints.ts) define the expected source-line hash. A custom namespaced Sentinel fingerprint preserves issue identity separately. |
| A simple SQLite version floor is sufficient | [SQLite changes](https://sqlite.org/changes.html) records fixes in 3.51.3/3.53.0 and withdrawal of 3.52.0. Gate verified fixed families or documented backports, not only a numeric lower bound. |
| Canary fixtures prove comments cannot change verdicts; deterministic silence disagreement measures misses | [OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) motivates layered controls and tests, not universal immunity. A paired repeated-trial result is evidence for that corpus; labeled ground truth is needed to distinguish misses from deterministic false positives. No E5 result or threshold approval is claimed. |
| Generated code always requires an approved build profile | Already generated source present in an authorized snapshot can be inventoried without executing a build. Producing absent generated source or compiled bytecode can require the owner's isolated-build decision. The owner question remains verbatim rather than being answered here. |
