Property · Street · Neighbourhood

One whiteboard, three altitudes. Zoom out and the journeys of an application sit side by side as neighbourhoods. Zoom into one and its screens line up along a street, each with its own pathway of calls and data underneath on demand. Zoom onto a screen and it snaps into the property view, where the screenshot is the hero and a tabbed rail holds everything Farsight knows about it. Below the working prototype are the alternative directions for each level, drawn rough on purpose, so we can cut before building.

Example data. Every screen, API, record, gate, test and work item here comes from the examples/invoice-app fixture that the e2e suite runs on, lightly dressed (work keys, commits and the accounts service's customer list are invented to show the shape). Numbers are illustrative, not measured.

1 · The working prototype

Drag to pan. Pinch, ⌘/Ctrl + scroll, or the + − buttons zoom. Plain scrolling pans, as in Miro and Figma. Zoom past a screen and it snaps into the property view; zoom back out and you land on the street. Esc backs out one level, ← → step between screens in the property, p toggles plumbing, b switches the lens, f goes full screen.

3 · One explorable card, every kind

Street plumbing only works if an API, a record, a message, a third party, a gate and a test all open the same way. The prototype uses one card anatomy for all of them, drawn from the graph's existing node fields, so the same card can later back the code map, the APIs tab and MCP answers without a second design.

  1. Kind and direction. The node kind in words, and for data nodes whether this step reads or writes. The kind colour is the graph's own (route cyan, table violet, gate purple, warn amber).
  2. Evidence class. Spec-backed, implied, not built, not indexed. The same closed set the rest of the product prints, never a new word.
  3. The name in the current register. Business lens shows the spec summary or the sentence a person wrote. Hybrid adds the identifier underneath.
  4. The identifier line is a code element and disappears in the business lens, so lint rule 5 holds without a second template.
  5. Counts as Counted. Each chip is a number, a word and a scope, with the tooltip from the catalog's define. Nothing summed across hops.
  6. Where it appears. The screens (and, from the neighbourhood, the journeys) this node is reached from. Each chip travels there.
  7. Two actions at most. Open on the surface that owns it, and Impact. The card is a doorway, not a second inspector.

5 · What the review should decide

Where it lives

Portfolio gains a Map option next to the table: the same journeys, drawn. The journey row's existing views stay. The option is a workspace flag like the action drill until it earns its place.

Plumbing default

Off at street level, on by the p key and a chip, remembered per viewer. Business lens with plumbing on shows read and write words and spec summaries, never identifiers.

Snap feel

Snap on gesture end versus a dedicated "enter" control. The prototype does both. Pick one as primary so touch and trackpad behave the same.

Tab count

Eight tabs fit the rail in two rows at 352 px. Fold Route into Overview and Changes into Work to get to six, or keep eight and accept the second row.

Missing screenshots

The placeholder shows the glyph, the screen name, the route and the components Farsight found. Paste or upload goes to a bonus stream that writes the image path into the source's design manifest.

Work and changes scope

Only commits and work items that touched the parts on this screen, by the existing commit-to-function credit. Journey level aggregates them the same way, never the whole repo.
